## Fixes

- **watch every root-middleware extension the server loads** ([#1101](https://github.com/webjsdev/webjs/pull/1101)) [`e07ea3a1`](https://github.com/webjsdev/webjs/commit/e07ea3a1)

  `webjs dev` added a `--watch-path` for `middleware.ts` and `middleware.js` only, while the server resolves four extensions. An app with a root `middleware.mts` or `middleware.mjs` loaded its middleware but never restarted the dev server when it was edited, which is the quiet half of the bug where a root `middleware.ts` was loaded by neither.

  A drift test now reads the server's own candidate list rather than restating it, so the two cannot diverge again.

- **point the scaffold and CLI output at `webjs.dev/docs`** ([#1101](https://github.com/webjsdev/webjs/pull/1101)) [`e07ea3a1`](https://github.com/webjsdev/webjs/commit/e07ea3a1)

  The documentation moved from `docs.webjs.dev` onto the main domain. A freshly scaffolded app carried the old host in its `AGENTS.md`, its agent rule files, the generated home page footer, and the gallery-clear script, and `webjs help` printed it too. The old host still redirects, so nothing was broken, but a new app should be generated with the current URL rather than one that costs every reader a redirect.
